# ADR 0001: モデル本来の判断契約を推奨 API にする

## 状態

採用。2026-10-07。

## 背景

PoC のクライアント API は変更可能。imajev は上流の型付き `Request` / `Result` により、判断保留、null の値、不明を含むスコア、校正情報を保持する。Jev 互換変換では判断保留時も choice 候補や score 期待値が返り、noul に不明スコアが混ざるため、モデル結果の意味をクライアントが把握しにくい。

## 決定

`POST /v1/decisions` を新規接続の推奨経路にする。上流契約を継承し、画像の data URL と8項目の公開上限を追加する。校正後の結果を維持し、内部 logits だけ除外する。判断保留時は `value: null` を必須とする。スコアを変換した独自の confidence は追加しない。

既存の `/v1/systemone` は上流互換経路として保持する。GPU と校正器、画像検証は共有する。新 API は FastAPI / OpenAPI で契約を公開し、要求にない項目を拒否する。

## 影響

クライアントは `fields` と `results`、`status` / `value` を使う。ordinal は段階の期待値ではなく選択段階なので、旧 score と同じ閾値をそのまま適用しない。正解付き評価と smoke test の既定経路も新 API にする。互換 API の評価は URL と事例の形式を明示して実施する。モデル重みと GitHub 配布 manifest は変更しない。

判断保留・不正入力・画像・校正条件・互換経路・OpenAPI を GPU なしで検証する。A10G 実機の測定は接続不可のため未実施。
